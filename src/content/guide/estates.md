Раздел **«Земельные проекты»** (`/estates`, `/ru/estates`) — это страницы под случай, когда **один собственник продаёт несколько участков** (большой чанот, нарезанный на лоты). Сделано по образцу раздела проектов застройщиков (`/projects`), но для земли: одна страница на всю подборку + таблица участков, где каждый лот помечен статусом.

## Что показывает страница подборки

- **Шапка** — название, район, число участков, суммарная площадь, слоган, фото-обложка.
- **Описание + плашка DD** — due diligence делается один раз по родительскому титулу и наследуется каждым лотом.
- **План разбивки** — интерактивная векторная схема в стиле RW: контуры лотов крашены по статусу (свободен/резерв/продан). Ориентация схемы сверена с кадастровыми координатами лотов: **север — вверху, закатное солнце — на западной кромке** (`plan.seaSide` в данных подборки). Наведение на лот подсвечивает строку в таблице и показывает детали лота в панели справа от схемы (площадь, вид, цена, кнопки); клик открывает карточку лота. Перекрашивается сам при смене статуса в данных. В тёмной теме полотно становится «ночной картой» — цвета живут в CSS-переменных `--esp-*` (класс `.site-plan` в `globals.css`).
- **Таблица участков** — по каждому лоту: площадь, вид владения, цена, чип вида (🌊 море / ⛰ горы), **статусный бейдж**; у свободных — кнопка «Запросить <лот>» (предзаполняет форму). Сверху — фильтр (все/свободные/море/горы) и сортировка (цена/площадь).
- **Фото с участков** — галерея, сгруппированная по лоту; клик открывает полноэкранный лайтбокс с каруселью.
- **Карта** (если заданы координаты), форма заявки, ссылка «все объекты района».

## Четыре статуса лота

- **Свободен** (available) — яркий латунный бейдж, лот в продаже/аренде.
- **Резерв** (reserved) — внесён задаток.
- **Продан** (sold) — фрихолд-лот продан.
- **Арендован** (rented) — лизхолд-лот сдан в долгосрочную аренду.

Цена/аренда показывается **только** для свободных и зарезервированных лотов; по проданным/арендованным публично виден только статус (цены закрытых сделок не раскрываем).

## Как завести/изменить подборку

Подборки курируются вручную в файле **`web/src/content/land-estates.ts`** (как районы и база знаний — это не каталог amoCRM). Один объект `LandEstate` = одна страница.

1. Добавить объект в массив `LAND_ESTATES`: `slug`, двуязычные `name`/`tagline`/`description`, `district` (точно как в amoCRM — для ссылки на район), координаты, массив `plots`.
2. Каждый лот `plots[]`: `code` («R7», «M1»), `status`, `tenure`, площадь (`areaSqm` или `areaRai`), цена (`priceThb`) или аренда (`rentPerRaiMonth` + `leaseTermYears`). Опционально `rwNumber` — привязка к реальной карточке каталога: свободный лот с `rwNumber` становится кликабельным → `/object/RW-L####`.
3. **Фото лота:** массив `photos` у лота (пути под `/public`, например `/images/estates/<slug>/r7-1.jpg`) — кладёшь файлы в `web/public/images/estates/<slug>/`, прописываешь пути, и фото появляются в секции «Фото с участков», сгруппированные по лоту. Пока файлов нет — оставляем `photos` пустым (без битых картинок).
4. **Публикация:** `published: true` выводит подборку на сайт; `false` — черновик (не в индексе, страница отдаёт 404). На прод выводить только реальные данные.

> 🔒 **Контакты собственника и лидов в этот файл НЕ кладём** и на сайт не выводим — они в рабочем хабе (оперативка), лиды — в CRM.

**Первый реальный кейс — `haad-yao-hillside`** (склон над Хад Яо): один собственник, родительский титул нарезан на два ряда лотов — **R** (закатный вид на море) и **M** (вид на горы). 12 лотов, свободны R1/R7/R10/M1/M2/M10, продано R2/R5/R6/R34/M3/M4. Цены R1/R7 — из открытого каталога застройщика, по остальным свободным — «по запросу» (уточняем). По **M10** чанот ещё не оформлен — это отражено в заметке лота (наглядный пример честного DD: проверяем индивидуальный чанот по каждому лоту до резерва).

Раздел двуязычный (EN+RU), есть OG-картинки, JSON-LD (CollectionPage + ItemList со статусами наличия) и записи в sitemap. Пункт меню — «Estates» / «Участки».
